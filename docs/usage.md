# Usage Guide

## Overview

The SHA-256 demo has two executable components:

1. `sha256/server/server.go` starts an HTTPS server and accepts multipart uploads on `/upload`.
2. `sha256/client/client.go` reads `sha256/client/data/input-file.txt`, creates a timestamped multipart filename, uploads it, and prints the server response.

The server computes the SHA-256 digest while saving the uploaded file. This lets the response describe the exact bytes that were written to disk.

## Prerequisites

- Go 1.22 or newer.
- Port `8080` available on localhost.
- The included local development certificate and key:
  - `sha256/certs/server.crt`
  - `sha256/certs/server.key`

## Start the HTTPS server

Run the server from its package directory so the relative certificate and upload paths resolve correctly:

```bash
cd sha256/server
go run server.go
```

Expected startup message:

```text
HTTPS Server running on https://localhost:8080
```

The server accepts only `POST` requests on `/upload`. The multipart form must include a file field named `file`.

## Upload a file with the client

Open a second terminal and run:

```bash
cd sha256/client
go run client.go
```

The client uploads `data/input-file.txt` and prints a response like:

```text
File uploaded successfully
SHA256: <64-character-hex-digest>
```

The uploaded file is saved by the server under `sha256/server/data/uploads/` with the timestamped filename generated by the client.

## Verify the digest manually

After an upload, compare the server response with a local SHA-256 digest of the source file:

```bash
sha256sum sha256/client/data/input-file.txt
```

The digest should match the `SHA256:` value returned by the server if the same file bytes were uploaded and saved.

## Troubleshooting

### `bind: address already in use`

Another process is already using port `8080`. Stop that process or change the server address in `sha256/server/server.go`.

### Certificate trust errors

The client trusts only `sha256/certs/server.crt`. Ensure the server is using the matching certificate/key pair and that the client is run from `sha256/client` so `../certs/server.crt` resolves correctly.

### `Unable to save file`

Create the upload directory if it is missing:

```bash
mkdir -p sha256/server/data/uploads
```

Then restart the server from `sha256/server`.
